## Trap Doors

- `process-liveness.ts` (AP-EXT-ITER33-01 EPERM is not proof of death) — INVARIANT: `isProcessAlive` is the ONE pid-liveness probe (state-manager re-exports it; recoverable-json, resolve-state, pipeline-runner and stop-hook import it, none re-inlines one), and it answers positive-death-only: `process.kill(pid, 0)` throwing `EPERM` means the process EXISTS under another euid, so only a non-EPERM throw reads dead. A non-integer/non-positive pid also reads alive — `kill(0)`/`kill(-n)` address the caller's own process GROUP and must never reach the probe. BREAKS: five copies of `try { process.kill(pid,0); return true } catch { return false }` shipped, four of them collapsing EPERM into death, and that false licenses a destroy at every consumer — `isDeadPidPayload` evicts a LIVE holder's `state.json` lock (two writers in the critical section, the catastrophe `lock-steal-live-holder.test.js` exists to prevent), `orphan-reaper` group-SIGKILLs a live sibling worker mid-build, `pickle-utils` demotes a live session out of the map. `stop-hook.ts` was the ONE correct copy and proved the intended contract. ENFORCE: extension/tests/integration/lock-steal-live-holder.test.js (`AP-EXT-ITER33-01` — asserts the STEAL VERDICT and the lockfile on disk, both arms; a boolean-return oracle greens the moment the errno re-widens and the caller re-narrows). PATTERN_SHAPE: exactly one `function isProcessAlive(` in `extension/src/`, in `lib/process-liveness.ts`, whose catch reads `err.code === 'EPERM'`; zero `process.kill(<pid>, 0)` liveness probes outside it (a `kill(pid,0)`-then-SIGTERM teardown is not a probe).

- `salvage-ticket.ts` (AP-EXT-ITER10-01 partial dep injection MERGES) — INVARIANT: `salvageTicket` takes `Partial<SalvageDeps>` and spreads it over `defaultDeps` (undefined-valued keys dropped); callers MUST NOT cast a partial to `SalvageDeps`.
